(1b) current_holdings_extended（OPTIONAL；若目前持有任何 extended ETF，無論本回合 optional_extended_etf_sleeve.enabled=true/false 都應提供）
格式：TICKER | shares | avg_cost
- TICKER 必須屬於 RESEARCH_JSON.optional_extended_etf_sleeve.allowed_extended_etf_tickers，或屬於使用者既有 extended ETF 持倉清單
- 若未持有可不提供
- shares 必須為整數且 >=0
- avg_cost 允許為 NA/null
- 若本回合 enabled=false 但仍持有 extended ETF，仍必須提供，供 extended_etf_disable_handling_rule 判定 keep / reduce / sell

- extended_etf_disable_handling_rule (NEW, MUST):
  - 若 current_holdings_extended 存在，但本回合 RESEARCH_JSON.optional_extended_etf_sleeve.enabled = false：
      (a) 不得僅因 disabled 就自動 sell_all
      (b) 只能 keep / reduce，除非 thesis_invalidated 或 relative_expected_return_rotation 成立
      (c) 若 reduce / sell，理由必須明確包含：
          REPLACEMENT_TARGET: {ticker}
          WHY_NOT_KEEP: {一句話，繁體中文}

- existing_extended_holdings_ssot_rule (NEW, MUST):
  - 若 current_holdings_extended 有提供，則「使用者既有 extended ETF 持倉清單」的唯一 SSOT = current_holdings_extended 內出現的 ticker 集合
  - 模型不得自行假設其他 extended ETF 屬於既有持倉
  - 若某 extended ETF 不在 current_holdings_extended，則不得被視為 existing holding，只能視為本回合新候選

(2a) existing_buy_open_orders_summary（optional, ticker-level summary; buy-side existing open orders SSOT）

- 若此區塊缺失，或此區塊存在但無任何資料列：視為沒有既有 buy open orders；模型不得假設市場上已有買單
- parsing_rule: "Portfolio Snapshot 的 budget 若含逗號（如 2,500 / 8,000），計算前必須先移除逗號再做加總/占比。"

- open_orders_anchor_state_rule (NEW, MUST):
  - 為了讓 keep/reduce 時能決定是否 reanchor / mini-reanchor，你必須為每個 ticker 提供「上次下單時使用的錨定基準」：
    anchor_baseline_last_close 與 anchor_price_asof
  - anchor_baseline_last_close 定義：
    上一次你生成/重掛該 ticker 買單時所採用的 baseline last_close
  - anchor_price_asof 定義：
    該 baseline 的收盤日（YYYY-MM-DD, ET）
  - last_refresh_date_et（optional）：
    你上次實際取消/重掛該 ticker 買單的日期（ET）；若缺則視為未知，不用年齡觸發，只用漂移觸發
  - 若 anchor_baseline_last_close 或 anchor_price_asof 缺失：
    視為 DATA_GAP；本回合該 ticker 允許 keep / reduce / cancel，但不得觸發 mini-reanchor / reanchor

格式（UPDATED）：

TICKER | budget | compiled_open_order_notional(optional) | residual_cash_not_allocated(optional) | template_id | anchor_baseline_last_close | anchor_price_asof | last_refresh_date_et(optional) | highest_live_limit(optional) | lowest_live_limit(optional) | live_step_count(optional) | live_order_steps_summary(optional) | live_order_qtys_summary(optional)

- column_position_preservation_rule (NEW, MUST):
  - existing_buy_open_orders_summary 的每一資料列都必須嚴格維持欄位順序
  - 即使 compiled_open_order_notional / residual_cash_not_allocated / last_refresh_date_et 等 optional 欄位缺值，也必須保留空欄位置，不得省略分隔欄位
  - 不得因 optional middle fields 缺值而讓 template_id、anchor_baseline_last_close 或後續欄位左移
  - 若資料列欄位數與格式定義不一致，Strategy C 必須視為 DATA_GAP / PARSE_BLOCKED

- budget_vs_live_notional_rule (NEW, MUST):
  - budget = 該 ticker 的 target / reserved open-order budget bucket
  - compiled_open_order_notional = 目前 live buy orders 的實際名目金額總和
  - residual_cash_not_allocated = budget - compiled_open_order_notional
  - Strategy C 不得把 budget 與 compiled_open_order_notional 視為必然相等
  - 若存在整股限制、weighted ladder、preserve_live_qty_vector 或 top_up_rule 缺失，compiled_open_order_notional 可以明顯低於 budget；此差額必須保留，不得默默吞掉

- compiled_open_order_notional_reconstruction_rule (NEW, MUST):
  - 若 live_order_steps_summary 與 live_order_qtys_summary 可 deterministic 解析：
    compiled_open_order_notional = Σ(step_shares_i × step_limit_price_i)
  - residual_cash_not_allocated = budget - compiled_open_order_notional
  - Strategy C 與後續 Portfolio Snapshot / ORDER_STATE_EXPORT 應優先保留這兩個欄位，而不是只保留 budget

- new_order_state_export_rule (NEW, MUST):
  - 對於本回合由 Strategy C 新生成、且要寫入 ORDER_STATE_EXPORT 的 buy open orders：
    - 必須輸出 compiled_open_order_notional
    - 必須輸出 residual_cash_not_allocated
  - 不得只輸出 budget 而省略實際已編譯出的 live notional
  - 若因資料格式限制暫時無法輸出，必須在 TEMPLATE5_EXEC_SUMMARY 明確列為 DATA_GAP / EXPORT_GAP

- keep_existing_state_carry_forward_rule (NEW, MUST):
  - 若某 ticker 在 current live SSOT 已存在，且本回合 final_action = "KEEP_EXISTING"：
    - compiled_open_order_notional
    - residual_cash_not_allocated
    - highest_live_limit
    - lowest_live_limit
    - live_step_count
    - live_order_steps_summary
    - live_order_qtys_summary
    應優先沿用 current live SSOT 的既有值
  - 不得因為輸出 post-submission intended SSOT，就省略、重算或改寫上述欄位
  - 除非 AUDITED_DECISION_PACKET 已明示 replace / reanchor / cancel，否則 KEEP_EXISTING 不得改變上述 live-state 欄位

- live_buy_order_structure_rule (NEW, MUST):
  - existing_buy_open_orders_summary 除了 baseline 外，還必須盡量保留目前 live 買單價格結構摘要：
    - highest_live_limit = 目前尚未成交的最高買入限價
    - lowest_live_limit = 目前尚未成交的最低買入限價
    - live_step_count = 目前 live、未成交的 BUY step 數量
    - live_order_steps_summary = 目前 live buy order 的 step 與價格摘要
    - live_order_qtys_summary = 目前 live buy order 各 step 的剩餘股數摘要
  - live_order_steps_summary 與 live_order_qtys_summary 的 step 名稱必須一致

- data_gap_behavior_for_live_structure (NEW, MUST):
  - 若 highest_live_limit / lowest_live_limit / live_step_count / live_order_steps_summary / live_order_qtys_summary 全部缺失：
    - 不得僅靠 baseline 推定原掛單成交機率仍合理
    - 允許 keep / cancel / baseline-based mini_reanchor / baseline-based reanchor
    - 但 reason 必須明確寫：
      "DATA_GAP: live order price structure missing; fill probability inferred from baseline only"

- live_step_count_definition_rule (NEW, MUST):
  - live_step_count = 目前市場上仍有效的未成交 BUY steps 數量
  - 若 live_step_count 缺失，且 live_order_steps_summary 也無法可靠解析：
    - 不得憑空假設 step 數量
    - 不得輸出 preserve_existing_step_shape / preserve_existing_live_qty 類型的 replace-style packet

- summary_ssot_rule_for_buy_open_orders (NEW, MUST):
  - existing_buy_open_orders_summary 是 buy-side existing open orders 的唯一 SSOT
  - A = Σ(existing_buy_open_orders_summary budgets)
  - 若其中 ticker 不在 effective_allowed_buy_universe：
      action 必須 = cancel
      new_budget 必須 = 0
      且不得輸出該 ticker 的 Execution Plan / BUY_ORDERS

- post_submission_state_metadata_rule（OPTIONAL BUT RECOMMENDED）：
  - 若 Portfolio Snapshot 是在當日 weekly-approved orders 實際下單 / cancel-replace / 重掛之後更新，建議在 snapshot header 或 operator notes 中標示：
      open_order_state_asof_et: YYYY-MM-DD HH:MM ET
      open_order_state_timing: post_submission / post_close / pre_submission
      broker_submission_confirmed: true/false/unknown
      fills_asof_et: YYYY-MM-DD HH:MM ET 或 unknown
      remaining_qty_confirmed: true/false/unknown
  - 若未提供上述 metadata，但 existing_buy_open_orders_summary 明確已反映當日 replacement 後 ladder，Daily Execution Check 可將該 row 視為 operator-provided current state。
  - 若 open_order_state_timing=pre_submission 或 broker_submission_confirmed=false，Daily Execution Check 不得把 replacement 後 intended ladder 視為 live state。

(2b) sell_open_orders（optional, lot-aware open sell orders summary）

- sell_open_orders_state_rule:
  - 目的：讓下次 run 能追蹤市場中已存在的 SELL open orders，並判定 keep / reduce / increase / replace / cancel
  - 若此區塊缺失，或此區塊存在但無任何資料列：視為沒有既有 sell open orders；模型不得假設市場上已有賣單

格式（UPDATED）：
TICKER | shares_to_sell | limit_price | tax_lot_source | lot_selection_mode | acquired_date_ref | lot_id | anchor_baseline_last_close | anchor_price_asof | last_refresh_date_et(optional)

定義：
- shares_to_sell: 目前市場上該筆 SELL open order 的未成交股數
- limit_price: 目前市場上該筆 SELL open order 的限價
- tax_lot_source:
  - 只能是：
    - LTCG_ELIGIBLE_SELLABLE
    - ESPP_DISPOSITION_CANDIDATES
    - NON_LTCG_OVERRIDE_CANDIDATES
- lot_selection_mode:
  - 若 tax_lot_source=LTCG_ELIGIBLE_SELLABLE，必須 = "specific-lot long_term_only"
  - 若 tax_lot_source=ESPP_DISPOSITION_CANDIDATES，必須 = "specific-lot exact_lot"
  - 若 tax_lot_source=NON_LTCG_OVERRIDE_CANDIDATES，必須 = "specific-lot exact_lot"
- acquired_date_ref:
  - 若 tax_lot_source=LTCG_ELIGIBLE_SELLABLE，對應 LTCG_ELIGIBLE_SELLABLE 的 acquired_before_date
  - 若 tax_lot_source=ESPP_DISPOSITION_CANDIDATES，對應 ESPP_DISPOSITION_CANDIDATES 的 transfer_date
  - 若 tax_lot_source=NON_LTCG_OVERRIDE_CANDIDATES，對應 NON_LTCG_OVERRIDE_CANDIDATES 的 acquired_date
- lot_id:
  - 必須與對應來源區塊的 lot_id 一致
- anchor_baseline_last_close:
  - 上次生成/重掛該 SELL 單時所用的 baseline last_close
- anchor_price_asof:
  - 該 baseline 的收盤日（YYYY-MM-DD, ET）
- last_refresh_date_et:
  - 上次實際取消/重掛該 SELL 單的日期（ET）；若缺則只用價格漂移判定，不用年齡判定

若 anchor_baseline_last_close 或 anchor_price_asof 缺失：
- 視為 DATA_GAP
- 允許 keep / reduce / cancel
- 不得自動 replace / reanchor

- open_orders_input_hierarchy_rule (REVISED, MUST):
  - existing_buy_open_orders_summary 為 buy-side existing open orders 的唯一 SSOT，用於：
      (a) A = Σ(existing_buy_open_orders_summary budgets)
      (b) cap / headroom / B 計算
      (c) buy-side non-universe open order checks
      (d) buy-side anchor_decision / anchor_baseline_shift / order_intent = REPLACE_EXISTING 的可用性判定
  - sell_open_orders 為 sell-side existing open orders 的唯一 SSOT，用於：
      (a) sell-side keep / reduce / replace / cancel 判定
      (b) sell-side order_intent / anchor_decision / anchor_baseline_shift 的可用性判定
  - sell_open_orders 不得用於推導 A，因其不提供 buy-side budget
  - 若 existing_buy_open_orders_summary 有提供，buy-side 狀態判定與 buy-side 預算彙總皆以 existing_buy_open_orders_summary 為準
  - 若 existing_buy_open_orders_summary 未提供：
      A_from_snapshot = 0
      並標註 ASSUMPTION: no existing buy-side open orders provided
