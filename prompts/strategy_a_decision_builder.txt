2.49) Market-Data Numeric Unit Normalization (NEW, MUST)

- 所有 market data 數值欄位在 TEMPLATE2_OUTPUT 與 DECISION_PACKET 中都必須輸出為 parser-friendly numeric form；不得保留 human-readable shorthand。
- volume / avg volume / avg_volume_3m / liquidity volume 類欄位必須正規化為完整整數股數，不得輸出 K / M / B / T 後綴字串。
- 若來源提供縮寫：
  - "K" = × 1,000
  - "M" = × 1,000,000
  - "B" = × 1,000,000,000
  - "T" = × 1,000,000,000,000
- 範例：
  - "4.35M" 必須輸出為 4350000
  - "44.3M" 必須輸出為 44300000
  - "2.87M" 必須輸出為 2870000
  - "950K" 必須輸出為 950000
- 若來源提供 comma-formatted numeric string，例如 "4,350,000"，必須移除逗號並輸出為 number：4350000。
- 若來源提供小數縮寫，轉換後必須四捨五入為最接近的整數股數；不得保留小數。
- TEMPLATE2_OUTPUT.2.2 MARKET_DATA_TABLE 的 avg_volume_3m 欄位必須輸出完整整數，例如 4350000，不得輸出 "4.35M"。
- DECISION_PACKET.MARKET_DATA_SNAPSHOT.tickers[*].avg_volume_3m 必須輸出 JSON number，例如 4350000，不得輸出 JSON string "4.35M"。
- 若 volume / avg_volume_3m 無法取得，才可輸出 null；不得用 "NA"、"N/A"、"unknown" 或 shorthand 字串代替。
- 此正規化只改變數值表示格式，不得改變 liquidity_tier、quadrant、ranking、budget、delta 或任何投資判斷。

  - Decision Builder 在輸出任何 2.7 ROTATION_DECISION_8_15 row、或任何由 rotation 派生的 buy-side cancel/new replacement pair 前，必須先逐條套用 guardrails；不得把此檢查完全留給 Strategy B。
- require_same_role_for_rotation = true：
  - from_ticker 與 to_ticker 必須屬於同一 role_layer。
  - 若不同 role_layer：
    - 不得輸出 rotation row
    - 不得輸出由該 rotation 派生的 CANCEL_EXISTING / NEW_ORDER replacement pair
- min_score_gap_to_rotate = N：
  - Decision Builder 必須先固定本回合 rotation 的 controlling ordering dimension。
  - 若本 prompt / Strategy Settings 未另行明示，controlling ordering dimension SSOT = RESEARCH_JSON.buy_universe_scorecard[*].execution_priority_this_run。
  - 僅當 to_ticker 相對 from_ticker 的改善幅度 >= N 時，rotation 才可成立。
  - 若改善幅度 < N：
    - 不得輸出 rotation row
    - 應優先收斂為 KEEP_EXISTING / HOLD_NO_NEW_BUDGET
- do_not_rotate_if_current_holding_still_role_valid = true：
  - 若 from_ticker 的 current holding 或 existing buy open order 仍符合其 role_job，且不存在：
    (a) thesis_invalidated
    (b) policy breach
    (c) explicit role-layer conflict
    (d) clear non-tradeable / compile-blocked condition
    則不得僅因 to_ticker 排名略高而強制 rotation。
  - 在此情況下，應優先收斂為：
    - KEEP_EXISTING（若已有 live open order）
    - HOLD_NO_NEW_BUDGET（若僅不再加碼）
- 若 rotation 成立：
  - 2.7 ROTATION_DECISION_8_15.why 必須以以下格式開頭：
    "ROTATION_BASIS: execution_priority_this_run; SCORE_GAP: {value}; ROLE_COMPATIBLE: true;"
  - 不得只寫泛稱的「rank 較高」或「優先度較高」而不說明控制維度與 gap。

  - "funded"
  - "watch_only"
  - "held_no_new_budget"

  - why 必須以 "NO_NEW_BUDGET:" 開頭，明確說明原因。
- 不得把 shortlist 入選，直接等同於一定會產生 BUY_ORDERS。

  role cap 先於 watch-only / held_no_new_budget 判定。

12A) Reanchor Notional Feasibility Gate (NEW, MUST)
- 若 buy-side execution draft 同時滿足以下條件：
  - order_intent = "REPLACE_EXISTING"
  - anchor_decision 屬於 "mini_reanchor_candidate" / "full_reanchor_candidate"
  - preserve_live_step_shape = true
  - preserve_live_qty_vector 存在
  - current_last_close 與 step_offsets_vs_anchor 已可取得
- 則在輸出該 row 前，必須先做 reanchor 後預算可行性檢查。
- 重算方式：
  - 以 current_last_close 作為新 anchor
  - 依 step_offsets_vs_anchor 推回各 rung 的新 limit price
  - 再用 preserve_live_qty_vector 重算 reanchored_estimated_total_notional
- 若 reanchored_estimated_total_notional <= proposed_budget：
  - 方可保留 preserve_live_qty_vector 輸出 execution draft row
- 若 reanchored_estimated_total_notional > proposed_budget：
  - 不得直接保留 preserve_live_qty_vector 輸出
  - 若可 deterministic 產生 step_budget_weights：
      - 該 row 必須改輸出 step_budget_weights
      - preserve_live_qty_vector 不得再作為 compile payload
  - 若無法 deterministic 產生 step_budget_weights：
      - 不得輸出該 execution draft row
      - 必須在 ASSUMPTIONS_AND_DATA_GAPS 註記：
        UPSTREAM_EXECUTION_DATA_GAP: reanchor notional infeasible under preserve_live_qty_vector
- Decision Builder 不得把「保留原 qty vector」與「維持原 proposed_budget」同時視為已成立，除非上述可行性檢查已通過。

12B) Executable Action vs Compile Contract Closure (NEW, MUST)
- 對任何 buy-side row，若同時滿足以下任一條件：
  - proposed_budget > 0
  - order_intent 屬於 "NEW_ORDER" / "REPLACE_EXISTING" / "CANCEL_EXISTING"
- 則 Decision Builder 必須在輸出前先判定該 row 是否 compile-closed。
- compile-closed 的最低標準：
  - template_id 已 deterministic 決定
  - execution draft row 已存在
  - 不需要 Strategy B / Strategy C 反向補推 step 名稱、qty 規則、anchor 或 intended_place_date_et
- 若不滿足 compile-closed：
  - buy-side delta row 的 why 必須以 "COMPILE_BLOCKED:" 開頭
  - 必須在 ASSUMPTIONS_AND_DATA_GAPS 註記：
    UPSTREAM_EXECUTION_DATA_GAP: compile contract incomplete for executable buy-side row
  - 不得把該 row 描述成可直接下游編譯 / compile-ready
- NEW_ORDER 的 template_id 只能來自以下來源之一：
  - Strategy Settings 內明確提供的 buy_order_template_map
  - 本 prompt 內明確提供的 deterministic template mapping

  - 不得輸出 execution draft row
  - 不得留待 Strategy B / Strategy C 補推

12C) Template Mapping Availability + Step-Weight Validity Gate (NEW, MUST)
- 若本回合可能產生任何 buy-side NEW_ORDER execution draft，則本 prompt 或 Strategy Settings 必須明確提供 deterministic template mapping。
- 若本回合未提供 buy_order_template_map，且本 prompt 內也未提供可直接套用的 deterministic template mapping：
