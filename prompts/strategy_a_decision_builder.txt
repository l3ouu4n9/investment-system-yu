2.49) Market-Data Numeric Unit Normalization (NEW, MUST)

- 所有 market data 數值欄位在 TEMPLATE2_OUTPUT 與 DECISION_PACKET 中都必須輸出為 parser-friendly numeric form；不得保留 human-readable shorthand。
- volume / avg volume / avg_volume_3m / liquidity volume 類欄位必須正規化為完整整數股數，不得輸出 K / M / B / T 後綴字串。
- 若來源提供縮寫：
  - "K" = × 1,000
  - "M" = × 1,000,000
  - "B" = × 1,000,000,000
  - "T" = × 1,000,000,000,000
- 範例：
  - "4.35M" 必須輸出為 4350000
  - "44.3M" 必須輸出為 44300000
  - "2.87M" 必須輸出為 2870000
  - "950K" 必須輸出為 950000
- 若來源提供 comma-formatted numeric string，例如 "4,350,000"，必須移除逗號並輸出為 number：4350000。
- 若來源提供小數縮寫，轉換後必須四捨五入為最接近的整數股數；不得保留小數。
- TEMPLATE2_OUTPUT.2.2 MARKET_DATA_TABLE 的 avg_volume_3m 欄位必須輸出完整整數，例如 4350000，不得輸出 "4.35M"。
- DECISION_PACKET.MARKET_DATA_SNAPSHOT.tickers[*].avg_volume_3m 必須輸出 JSON number，例如 4350000，不得輸出 JSON string "4.35M"。
- 若 volume / avg_volume_3m 無法取得，才可輸出 null；不得用 "NA"、"N/A"、"unknown" 或 shorthand 字串代替。

8A.1) Enabled Extended ETF Funding Source Evaluation（NEW, MUST）

- 若 optional_extended_etf_sleeve.enabled = true，且某 ticker 出現在 optional_extended_etf_sleeve.allowed_extended_etf_tickers：
  - 該 ticker 已可進入 Strategy A effective_allowed_buy_universe。
  - 該 ticker 若同時通過：
    - approved static list gate
    - activation gate
    - liquidity / AUM / spread gate
    - linkage gate
    - future scheduled theme anchor gate OR long_cycle_structural_theme_exception structural review anchor gate
    - 12m+ thesis gate
    - LLM model-risk controls
    - sleeve cap / single ETF cap / same-theme cap / same-run escalation gate
    - compile-closed gate
    但 hard_cap_open_orders_budget 的剩餘自然 headroom 低於 Strategy Settings.extended_etf_constraints.activation_minimum_effective_budget_pct_of_total_open_orders 所需的 minimum activation budget，
    Strategy A 不得直接以 "hard-cap headroom insufficient" / "headroom below activation minimum" / "no permitted funding rotation" 作為 HOLD_NO_NEW_BUDGET 的唯一理由。

- 在上述情況下，Strategy A 必須先執行 enabled_extended_etf_funding_source_evaluation，明確評估是否可從既有 buy open-order budget 釋放資金，以資助已通過 activation 的 enabled extended ETF。

- funding-source evaluation 的候選來源優先序固定如下：
  1. diversified_core_buffer existing open order，優先檢查 VOO
  2. lower-priority same-role buffer，例如 VTI / VT 若有既有 open order
  3. lower-conviction existing alpha sleeve
  4. residual / underallocated compiled-vs-budget slack，僅限 Strategy Settings / Portfolio Snapshot / downstream export contract 明確允許 reduce budget 或 reclaim slack 時

- QQQ / benchmark_carrier_core 不得作為預設 funding source。
- QQQ 只有在投資目標、Strategy Settings 或使用者本輪明確允許削弱 benchmark anchor 時，才可被列為 funding source；否則 evaluated_funding_source_tickers 不得把 QQQ 當作 recommended funding source。

- activation_minimum_budget 的 deterministic 計算方式：
  - activation_minimum_budget = round(hard_cap_open_orders_budget × Strategy Settings.extended_etf_constraints.activation_minimum_effective_budget_pct_of_total_open_orders, 2)
  - available_natural_headroom = open_order_budget_headroom
  - budget_reduction_needed = max(0, activation_minimum_budget - available_natural_headroom)

- 若 enabled extended ETF 具備更高 12m+ alpha upside、明確 incremental exposure、high_evidence 或 adequate_evidence、且不違反 cap / linkage / liquidity / compile gates，Strategy A 必須明確比較：
  A. 保留 diversified_core_buffer budget
  B. 削減 diversified_core_buffer budget 以資助 enabled extended ETF

- 若 Strategy A 選擇不削減 VOO / diversified_core_buffer，則必須使用 mandate-based reason 說明為何 preserve_buffer_hold_no_new_budget 更符合本輪投資目標。
- 合格的 mandate-based reason 可包含：
  - funding source 本身仍承擔必要 diversified buffer role，且削減會造成 QQQ-centered mandate 下的 portfolio balance 明顯惡化
  - enabled extended ETF 雖通過 activation，但本輪相對 funding source 的 12m+ expected return / incremental exposure advantage 不足
  - 削減 funding source 會違反 role cap、same-run escalation limit、sleeve cap、single ETF cap、same-theme cap、LLM model-risk controls 或 compile contract
  - funding source reduction 無法 deterministic compile / export，而不是單純因為比較麻煩
- 不合格理由包括但不限於：
  - "headroom insufficient"
  - "no natural cash"
  - "lower volatility"
  - "easier to compile"
  - "preserve buffer by default"
  - "extended ETF tracking error is higher"
  - "theme concentration is higher"
  上述理由不得單獨作為 preserve_buffer_hold_no_new_budget 的充分理由。

- 若 Strategy A 選擇 reduce_buffer_to_fund_extended_etf：
  - 必須在 buy_side_delta_table 中對 funding source ticker 輸出 REDUCE_EXISTING_BUDGET / REPLACE_EXISTING，或在需要完全取消該 funding source open order 時輸出 CANCEL_EXISTING。
  - 必須對 enabled extended ETF 輸出 NEW_ORDER / INCREASE / REPLACE_EXISTING，依該 ticker 是否已有 existing buy open order deterministic 決定。
  - Vocabulary normalization（MUST）：
    - "REDUCE_EXISTING_BUDGET" 與 "INCREASE" 只能作為 budget_change_type / explanation label，不得作為 order_intent、final_action_candidate、或 Strategy C executable final_action。
    - funding source ticker 若只是削減既有 open-order budget 並重新提交 ladder：
      - order_intent = "REPLACE_EXISTING"
      - final_action_candidate = "REPLACE_EXISTING"
      - budget_change_type = "REDUCE_EXISTING_BUDGET"
    - funding source ticker 若需完全取消既有 open order：
      - order_intent = "CANCEL_EXISTING"
      - final_action_candidate = "CANCEL_EXISTING"
      - budget_change_type = "CANCEL_EXISTING_BUDGET"
    - enabled extended ETF 若原本沒有 existing buy open order：
      - order_intent = "NEW_ORDER"
      - final_action_candidate = "NEW_ORDER"
      - budget_change_type = "NEW_EXTENDED_ETF_BUDGET"
    - enabled extended ETF 若已有 existing buy open order 且只是提高 / 重配 budget：
      - order_intent = "REPLACE_EXISTING"
      - final_action_candidate = "REPLACE_EXISTING"
      - budget_change_type = "INCREASE_EXISTING_EXTENDED_ETF_BUDGET"
    - Strategy A 不得把 "REDUCE_EXISTING_BUDGET" 或 "INCREASE" 輸出成 downstream executable action。
  - final proposed_buy_open_orders_budget_total 仍不得超過 hard_cap_open_orders_budget。
  - funding source reduction 與 enabled extended ETF new/increase/replacement 均必須 compile-closed。
  - 不得使用 sell proceeds 或同 run sell-side redeploy 來資助本輪 enabled extended ETF。

- 若 Strategy A 選擇 preserve_buffer_hold_no_new_budget：
  - 該 enabled extended ETF 仍可 final action = HOLD_NO_NEW_BUDGET。
  - 但 why 必須包含 funding-source evaluation 結論。
  - 不得只寫 hard-cap headroom insufficient / no permitted funding rotation。

- TEMPLATE2_OUTPUT 固定 pipe-table 欄位不得新增欄位。
- 在 TEMPLATE2_OUTPUT 中，若 enabled extended ETF 因 preserve_buffer_hold_no_new_budget 而不給新 budget：
  - 2.4 ACTIVE_SHORTLIST_TABLE 的 why 必須包含 parser-safe key=value 訊息：
    "FUNDING_SOURCE_EVALUATED: evaluated_funding_source_tickers=[...]; funding_source_decision=...; required_budget_for_activation=...; available_natural_headroom=...; budget_reduction_needed=...; why_preserve_buffer_over_enabled_extended_etf=..."
  - 2.6 BUY_SIDE_DELTA_TABLE 的 why 必須包含同樣的 parser-safe key=value 訊息。
  - 2.11 ASSUMPTIONS_AND_DATA_GAPS 必須新增 INFO row，明確記錄 evaluated_funding_source_tickers、funding_source_decision、required_budget_for_activation、available_natural_headroom、budget_reduction_needed。

- DECISION_PACKET JSON 中，對每個 enabled extended ETF 且 final action / action_draft 為 HOLD_NO_NEW_BUDGET 的 row，必須在 buy_side_delta_table[*] 內包含：
  "enabled_extended_etf_funding_source_evaluation": {
    "enabled_ticker": "...",
    "activation_minimum_budget": number,

    "recommended_funding_source_ticker": string|null,
    "funding_source_decision": "reduce_buffer_to_fund_extended_etf" | "preserve_buffer_hold_no_new_budget" | "blocked_by_cap_or_compile_contract" | "blocked_by_no_valid_funding_source",
    "why_preserve_buffer_over_enabled_extended_etf": string|null,
    "why_reduce_buffer_to_fund_extended_etf": string|null
  }

- 若該 enabled extended ETF 同時存在於 active_shortlist[*]，active_shortlist[*] 同 ticker row 也必須包含同一份 enabled_extended_etf_funding_source_evaluation，或包含指向 buy_side_delta_table 同 ticker evaluation 的 deterministic reference：
  "enabled_extended_etf_funding_source_evaluation_ref": "buy_side_delta_table.{ticker}.enabled_extended_etf_funding_source_evaluation"

- DECISION_PACKET.audit_handoff_summary 必須彙總所有 enabled extended ETF funding-source evaluations：
  "enabled_extended_etf_funding_source_evaluations": [
    {
      "enabled_ticker": "...",
      "activation_minimum_budget": number,

- 若 Strategy A 沒有做上述 funding-source evaluation：
  - 不得把該 enabled extended ETF final action / action_draft 設為 HOLD_NO_NEW_BUDGET。
  - 必須在 assumptions_and_data_gaps 中加入：
    "ENABLED_EXTENDED_ETF_FUNDING_SOURCE_EVALUATION_MISSING"
  - 必須在 audit_handoff_summary.audit_handoff_blockers 中加入：
    "ENABLED_EXTENDED_ETF_FUNDING_SOURCE_EVALUATION_MISSING"
  - decision_builder_ready_for_audit 必須依既有規則設為 false。

8A.1B) Post-Cancel Material Headroom Redeployment Review（NEW, MUST）

- 目的：當本輪因 CANCEL_EXISTING / REDUCE_EXISTING_BUDGET / non-effective universe removal 釋放出 material buy open-order budget headroom 時，Strategy A 必須主動評估是否應將釋放出的預算重新配置到更符合本策略 3–5y benchmark-relative mandate 的既有合格買單或 enabled extended ETF；不得直接把 material headroom preserve，除非有明確 mandate-based reason。
- 本規則只處理 buy open-order budget headroom，不處理 sell proceeds。
- 本規則不得違反 no same-run sell redeploy；若 headroom 來自 SELL_ORDERS 或 sell proceeds，仍不得用於本輪 buy budget。
- 本規則的 trigger：
  - 先計算：
    trigger_source_exists =
      any existing buy open order row has action_draft / final_action_candidate / final_action = "CANCEL_EXISTING"
      OR any existing buy open order row has proposed_budget < existing_budget
  - 若 trigger_source_exists = true，且下列任一條件成立：
    (1) released_buy_open_order_budget >= max(1000.00, round(hard_cap_open_orders_budget * 0.03, 2))
    (2) post_action_open_order_budget_headroom >= max(1000.00, round(hard_cap_open_orders_budget * 0.03, 2))
    則必須啟動 post_cancel_material_headroom_redeployment_review。
  - 若 trigger_source_exists = false，則 post_cancel_material_headroom_redeployment_review.triggered 必須 = false；不得只因自然 headroom 很大而套用 post-cancel review。
- released_buy_open_order_budget 的 deterministic 計算：
  - released_buy_open_order_budget = Σ(max(0, existing_budget - proposed_budget)) for buy-side rows with CANCEL_EXISTING / budget reduction
  - post_action_open_order_budget_headroom = hard_cap_open_orders_budget - proposed_buy_open_orders_budget_total
- DECISION_PACKET 必須每回合輸出 top-level object；觸發時填入實際 review，未觸發時輸出 triggered=false 與 redeployment_decision="not_triggered"：
  post_cancel_material_headroom_redeployment_review:
    triggered: true|false
    trigger_reason_codes: []
    released_buy_open_order_budget: number
    post_action_open_order_budget_headroom: number
    materiality_threshold: number
    cancelled_or_reduced_source_tickers: []
    candidate_redeployment_destinations: []
    evaluated_destination_tickers: []
    recommended_destination_tickers: []
    redeployment_decision: "not_triggered" | "redeploy_to_existing_qualified_orders" | "partial_redeploy_to_existing_qualified_orders" | "preserve_headroom_with_mandate_reason" | "blocked_by_cap_or_compile_contract" | "blocked_by_no_qualified_destination"
    redeployment_budget_total: number
    preserved_headroom_after_review: number
    why_redeploy: string|null
    why_preserve_headroom: string|null
    why_each_candidate_rejected: []
- candidate_redeployment_destinations 至少必須評估：
  (1) QQQ / benchmark_carrier_core，若 QQQ 仍具 actionability、future macro anchor、非空 linkage，且 core_deployment_diagnostics 不顯示過度部署；
  (2) 已在 active_shortlist 或 final buy-side delta 中具備 12m+ thesis、非空 linkage、compile-closed 的 sector_alpha_tilt，例如 SMH；
  (3) optional_extended_etf_sleeve.allowed_extended_etf_tickers 內的 enabled extended ETF，例如 GRID，且必須通過 approved static list / activation / liquidity / cap / LLM model-risk / future theme anchor 或 long_cycle_structural_theme_exception structural review anchor；
  (4) diversified_core_buffer，例如 VOO，但不得僅因較低波動或容易 compile 而優先於 QQQ / 合格 alpha sleeve；
  (5) 若 CIBR 或其他 approved static-list ETF 經 Research Template 啟用 long_cycle_structural_theme_exception 且進入 optional_extended_etf_sleeve.allowed_extended_etf_tickers，則必須評估其 KEEP_EXISTING / same-budget REPLACE_EXISTING / small slow-build，而不得僅因缺 near-term scheduled theme event 取消。
- evaluated_destination_tickers 不得包含：
  - proposed_only ETF
  - 不在 effective_allowed_buy_universe 的 ticker
  - 缺 12m+ thesis linkage 的 ticker
  - 不能 deterministic compile 的 ticker
  - QQQ 作為 funding source；QQQ 只能作 redeployment destination，除非使用者明確允許削弱 benchmark anchor
- 若 Strategy A 決定 redeploy_to_existing_qualified_orders 或 partial_redeploy_to_existing_qualified_orders：
  - 對已有 existing buy open order 的 destination ticker，executable action 必須收斂為：
    order_intent = "REPLACE_EXISTING"
    final_action_candidate = "REPLACE_EXISTING"
    budget_change_type = "INCREASE_EXISTING_BUY_OPEN_ORDER_BUDGET"
  - 對沒有 existing buy open order 的 destination ticker，executable action 必須收斂為：
    order_intent = "NEW_ORDER"
    final_action_candidate = "NEW_ORDER"
    budget_change_type = "NEW_BUY_OPEN_ORDER_BUDGET"
  - 每個 redeployment destination 必須有 compile-closed execution draft，包含 template_id、anchor、step names、step offsets、step_budget_weights 或合法 qty vector、event-window metadata、plan_type、time_in_force、expiry_if_gtd。
  - final proposed_buy_open_orders_budget_total 仍必須 <= hard_cap_open_orders_budget。
  - 不得因想用滿 hard cap 而把預算塞給 lower-alpha / lower-linkage / compile-convenient ETF。
- 若 Strategy A 決定 preserve_headroom_with_mandate_reason：
  - why_preserve_headroom 必須是非空 mandate-based reason，且明確比較為什麼不把 headroom 補到 QQQ / SMH / GRID / 其他 enabled extended ETF。
  - 合格 reason 可包含：
    - 所有可評估 destination 的 compile contract 不完整；
    - 加 budget 會違反 hard cap、sleeve cap、single ETF cap、same-theme cap、same-run escalation limit 或 LLM model-risk controls；
    - QQQ / SMH / GRID 等 destination 的 current open-order reachability / role deployment 已足夠，且增加 budget 反而會造成過度集中或偏離本輪 mandate；
    - Research / Decision Builder 判定本輪 forced deployment expected value 不足，preserve headroom 高於部署到 lower-alpha / lower-linkage ETF。
  - 不合格 reason 包含但不限於：
    - "hard cap is upper bound not target"
    - "no deterministic new-budget target"
    - "headroom preserved by default"
    - "lower volatility"
    - "easier to compile"
    - "avoid tracking error"
    - "extended ETF theme concentration is higher"
  - 上述不合格 reason 不得單獨作為 preserve material headroom 的充分理由。
- 若 Strategy A 沒有做本 post-cancel material headroom redeployment review：
  - 不得把 released material headroom 靜默 preserve。
  - assumptions_and_data_gaps 必須加入：
    "POST_CANCEL_MATERIAL_HEADROOM_REDEPLOYMENT_REVIEW_MISSING"
  - audit_handoff_summary.audit_handoff_blockers 必須加入：
    "POST_CANCEL_MATERIAL_HEADROOM_REDEPLOYMENT_REVIEW_MISSING"
  - decision_builder_ready_for_audit 必須依既有 blocker 規則設為 false。
- TEMPLATE2_OUTPUT requirements：
  - 若本規則 triggered=true，2.11 ASSUMPTIONS_AND_DATA_GAPS 必須新增 INFO 或 BLOCKER row，摘要：
    "POST_CANCEL_HEADROOM_REDEPLOYMENT_REVIEW: released_buy_open_order_budget=...; post_action_open_order_budget_headroom=...; evaluated_destination_tickers=[...]; redeployment_decision=...; redeployment_budget_total=...; preserved_headroom_after_review=..."
  - 若任何 buy_side_delta_table row 因本規則增加 / 不增加 budget，why 必須包含 parser-safe key=value：
    "POST_CANCEL_HEADROOM_REVIEW: released_budget=...; evaluated_destination_tickers=[...]; redeployment_decision=...; why=..."
- DECISION_PACKET.audit_handoff_summary 必須包含：
  post_cancel_material_headroom_redeployment_review: {same object or deterministic summary}

8A.2) Cold Regime Benchmark-Relative Deployment Decision Rule（NEW, MUST）

- 目的：當 RESEARCH_JSON 顯示 cold regime / equity risk-reward impaired / cash-T-bill opportunity cost material 時，Strategy A 必須用 QQQ-centered 3–5y benchmark-relative mandate 判斷本輪應部署、reanchor、HOLD_NO_NEW_BUDGET，或 preserve headroom；不得機械式為了用滿 hard_cap_open_orders_budget 而硬買，也不得把本系統改寫為 bond / cash allocation engine。

- Trigger：若 RESEARCH_JSON.cold_regime_benchmark_relative_opportunity_review.triggered = true，或 RESEARCH_JSON.regime_inputs / buy_universe_scorecard / optional_extended_etf_sleeve 顯示下列任一情況，必須啟動 cold_regime_benchmark_relative_deployment_review：
  (1) base_universe_deployment_posture ∈ {"ranking_hold_watch_only","preserve_headroom_if_no_actionable_anchor"}；
  (2) cash_tbill_opportunity_cost_material = true；
  (3) QQQ / core buy universe 的 actionability_status 非 actionable_this_run，且 hard_cap_open_orders_budget 仍有可部署 headroom；
  (4) sector_alpha_tilt 或 enabled extended ETF 有 12m+ thesis 但因 anchor / linkage / cap / compile gate 暫時不可部署；
  (5) Strategy A 原本會因 cash drag / hard cap / open-order deployment 壓力而新增或替換較低 expected value 的 ETF。

- 若未觸發，本規則不得改變既有 Post-QQQ Material Alpha Sleeve Priority Clarification、Enabled Extended ETF Funding Source Evaluation、Core ETF Deployment Adequacy Guardrail、active_shortlist_size_rule 或 hard_cap_open_orders_budget 流程。

- 觸發時，DECISION_PACKET 必須輸出 top-level object：
  cold_regime_benchmark_relative_deployment_review:
    triggered: true|false
    research_review_present: true|false
    trigger_reasons: []
    qqq_anchor_status: "maintain_anchor|adequately_anchored|underdeployment_review_needed|not_triggered"
    qualified_actionable_candidates: []
    blocked_or_watch_only_candidates: []
    cash_tbill_opportunity_cost_material: true|false
    preserve_headroom_allowed: true|false
    conclusion: "deploy_to_qqq_or_core|deploy_to_sector_alpha_tilt|deploy_to_enabled_extended_etf|preserve_headroom|not_triggered"
    objective_alignment_reason: "{繁體中文一句話}"

- Decision rules：
  (1) 若 QQQ / benchmark_carrier_core 存在 underdeployment risk、near-edge ladder、或 core_deployment_diagnostics.deployment_status="underdeployment_review_required"，不得用 cold regime 作為不處理 QQQ 的唯一理由。Strategy A 仍必須依 8B 輸出 core_deployment_diagnostics，並明確說明 KEEP_EXISTING / REPLACE_EXISTING / NEW_ORDER / HOLD_NO_NEW_BUDGET 的選擇。
  (2) 若 QQQ / core universe 仍有合格 12m+ thesis、future macro anchor、非空 linkage、compile-closed execution draft、且 cold market 只是 sentiment_or_drawdown_only，則 cold regime 不得阻止部署；冷市場應視為可能改善 entry compensation。
  (3) 若 sector_alpha_tilt 或 enabled extended ETF 具備更高 12m+ alpha upside、非空 linkage、liquidity / cap / LLM gates 通過，且 execution / anchor 可 deterministic compile，則不得因 cold regime、波動較高、tracking error 較高、或主題較集中而自動 HOLD_NO_NEW_BUDGET。
  (4) 若 enabled extended ETF 已通過 activation，但 available_natural_headroom 低於 activation minimum，Strategy A 仍必須先執行 8A.1 enabled_extended_etf_funding_source_evaluation；不得用 cold regime 直接跳過 funding-source evaluation。
  (5) 若所有可部署 ETF 都缺少 12m+ thesis linkage、future anchor、compile contract，或 Research 指出 equity risk/reward impaired 且本週 forced deployment expected value 不足，Strategy A 可選擇 conclusion="preserve_headroom"。
  (6) conclusion="preserve_headroom" 時，不得輸出 NEW_ORDER 或 increase budget 給低 alpha、低 linkage、只因較穩 / 較容易 compile / 較接近 benchmark 的 ETF。
  (7) conclusion="preserve_headroom" 不得被解讀為 chronic cash retention、低波動優先、或放棄 QQQ benchmark anchor；objective_alignment_reason 必須明確說明 preserve headroom 是因本輪 benchmark-relative expected value 不足，而不是因市場冷本身。
  (8) cash / T-bill / MMF / Treasury / bond ETF 只能作 opportunity-cost context；除非 ticker 已經由 optional_extended_etf_sleeve.allowed_extended_etf_tickers 放行，否則不得進入 effective_allowed_buy_universe / active_shortlist / buy_side_delta_table / execution_plan_drafts_8_5。
  (9) 若 Treasury / bond ETF 已由使用者 approved static list + optional_extended_etf_sleeve.allowed_extended_etf_tickers 放行，Strategy A 仍必須把它視為 enabled extended ETF，完整通過 activation、12m+ total-return thesis、liquidity、cap、LLM model-risk、linkage / long_cycle exception、compile-closed gates；不得因其低波動或避險屬性自動提高 priority。

- TEMPLATE2_OUTPUT requirements：
  - 若 cold_regime_benchmark_relative_deployment_review.triggered=true，2.11 ASSUMPTIONS_AND_DATA_GAPS 必須新增 INFO row，摘要：
    "COLD_REGIME_BENCHMARK_RELATIVE_REVIEW: conclusion=...; preserve_headroom_allowed=...; qqq_anchor_status=...; cash_tbill_opportunity_cost_material=..."
  - 若任何 active_shortlist 或 buy_side_delta_table row 因本規則 proposed_budget=0 / HOLD_NO_NEW_BUDGET，why 必須以 parser-safe 前綴開頭：
    "COLD_REGIME_REVIEW: "
  - 若 conclusion="preserve_headroom"，why 必須包含：
    "CONSTRAINT_DRIVEN_NOT_OBJECTIVE_SHIFT: benchmark-relative expected value insufficient; preserving headroom is higher EV than forcing lower-alpha deployment"

- Audit handoff requirements：
  - DECISION_PACKET.audit_handoff_summary 必須包含：
    cold_regime_benchmark_relative_deployment_review: {same object or deterministic summary}

8B) Core ETF Deployment Adequacy Guardrail（NEW, MUST）

- Strategy A 必須區分三層：
  (a) long-term allocation decision：是否需要維持 / 增強核心 ETF exposure；
  (b) weekly execution planning：是否應 keep existing / same-budget reanchor / new budget within cap / hold no new budget；
  (c) daily maintenance：是否只需 carry forward / same-budget execution-only reanchor。

- 對 benchmark_carrier_core ticker（QQQ），Daily Execution Check 的 KEEP 只代表前一個 daily run 尚未超過 execution drift threshold；不得被 Strategy A 解讀為 weekly 層面必然沒有 underdeployment risk。

- 若 Strategy Settings.etf_layer_execution_policy.layers.benchmark_carrier_core 存在，Strategy A 必須使用該 policy 判斷 QQQ 是否需要 core_deployment_diagnostic。

- 對 QQQ，若以下任一情況成立，Strategy A 必須在 DECISION_PACKET 中輸出 core_deployment_diagnostics：
  1. existing buy open order 的 highest_live_limit 已接近 daily policy near-edge，或 recent_daily_execution_diagnostics 明確顯示 near-edge；
  2. QQQ target / reserved open-order budget 長期存在，但 compiled_open_order_notional 或 fill progress 顯示部署不足；
  3. QQQ 是 benchmark carrier，但 open-order ladder 過深，導致實際 exposure deployment 可能低於策略意圖；
  4. hard_cap_open_orders_budget 有 headroom，但 QQQ 核心承載未被充分承接，且無明確風控理由；
  5. Daily / prior artifacts 明確輸出 repeated near-edge weekly review note。

- core_deployment_diagnostics 每筆至少包含：
  - ticker
  - role_layer
  - current_holding_shares

  - compiled_open_order_notional
  - residual_cash_not_allocated
  - highest_live_limit

  - anchor_drift_pct
  - near_edge_flags
  - deployment_status:
      "adequately_deployed"
      "watch_near_underdeployment"
      "underdeployment_review_required"
  - weekly_allowed_responses:
      "keep_existing"
      "same_budget_reanchor"
      "new_budget_if_hard_cap_and_strategy_allow"
      "hold_no_new_budget_with_explicit_reason"
  - why

- 若 deployment_status = "underdeployment_review_required"：
  - Strategy A 不得靜默輸出 KEEP_EXISTING 而不解釋。
  - Strategy A 必須在 final buy-side delta / execution draft / assumptions_and_data_gaps 中明確說明為何採取：
    - KEEP_EXISTING；
    - REPLACE_EXISTING；
    - NEW_ORDER / budget increase within hard cap；

  - 若 12m+ thesis、incremental exposure、event/theme linkage、liquidity、cap、compile contract 均成立，應依 alpha upside / thesis duration / benchmark drift risk 做受控評估。

8B.1) Existing Buy Open Order Weekly Reachability / Same-Budget Reanchor Gate（NEW, MUST）

- Strategy A 必須對 Portfolio Snapshot.existing_buy_open_orders_summary 中每一筆 existing buy open order 執行 weekly reachability / reanchor 判定；不得只對 QQQ 執行 core_deployment_diagnostics。
- 本 gate 是 weekly execution-planning gate，不是 Daily 自動交易；它只允許在同 ticker、同 role、同 thesis、同 budget 或 same remaining budget、且 compile-closed 的條件下，把失去可執行性的 live ladder 收斂為 same-budget REPLACE_EXISTING。
- 對每一筆 existing buy open order，Strategy A 必須使用 MARKET_DATA_SNAPSHOT.current_last_close / price_asof 與 Portfolio Snapshot.existing_buy_open_orders_summary 中的：
  - anchor_baseline_last_close
  - anchor_price_asof
  - highest_live_limit
  - lowest_live_limit
  - live_step_count
  - live_order_steps_summary
  - live_order_qtys_summary
  計算並輸出 existing_buy_order_diagnostics。
- 計算公式固定如下：
  - baseline_drift_pct = (current_last_close - anchor_baseline_last_close) / anchor_baseline_last_close * 100
  - distance_to_highest_live_limit_pct = (highest_live_limit - current_last_close) / current_last_close * 100
  - distance_to_lowest_live_limit_pct = (lowest_live_limit - current_last_close) / current_last_close * 100
- existing_buy_order_diagnostics 內的 drift 欄位 canonical name 必須使用 baseline_drift_pct；core_deployment_diagnostics 若需要 anchor_drift_pct，可 deterministic copy baseline_drift_pct 為 anchor_drift_pct，但不得兩者數值不一致。
- Strategy A 必須依 ticker 的 role_layer，讀取 Strategy Settings.daily_execution_drift_policy.keep_tolerance：
  - anchor_drift_abs_pct_static_cap[role_layer]
  - max_negative_distance_to_highest_live_limit_pct[role_layer]
- Strategy Settings.daily_execution_drift_policy.keep_tolerance.max_negative_distance_to_highest_live_limit_pct[role_layer] 是正數 magnitude，代表允許的最大負距離百分比；例如 6.0 代表 floor = -6.0%，不得解讀為 +6.0%。
- reachability_floor_pct = -abs(max_negative_distance_to_highest_live_limit_pct[role_layer])
- KEEP_EXISTING 只在下列條件全部成立時才可使用：
  - required live ladder fields are present and parseable
  - abs(baseline_drift_pct) <= anchor_drift_abs_pct_static_cap[role_layer]
  - distance_to_highest_live_limit_pct >= reachability_floor_pct
  - no override / thesis / role / event blocker requires hold or cancel
- 若 abs(baseline_drift_pct) 超過 role tolerance，或 distance_to_highest_live_limit_pct < reachability_floor_pct，Strategy A 不得把 why 寫成 "within tolerance" / "reachability remains within tolerance" / "baseline drift and reachability remain within role tolerance"。
- 若 threshold breached 且以下條件全部成立：
  - same ticker only
  - same existing_budget / same remaining budget only
  - weekly thesis / role / event binding preserved
  - no ranking change
  - no budget increase
  - Portfolio Snapshot current live row is complete and parseable
  - replacement can be computed deterministically from existing weekly-approved role/template and current same-budget constraints
  則 Strategy A 應輸出：
  - BUY_SIDE_DELTA_TABLE.action_draft = "REPLACE_EXISTING"
  - BUY_SIDE_DELTA_TABLE.order_intent_draft = "REPLACE_EXISTING"
  - BUY_SIDE_DELTA_TABLE.anchor_decision_draft = "mini_reanchor_candidate" 或 "full_reanchor_candidate"
  - EXECUTION_PLAN_DRAFTS_8_5.order_intent = "REPLACE_EXISTING"
  - EXECUTION_PLAN_DRAFTS_8_5.anchor_decision = "mini_reanchor_candidate" 或 "full_reanchor_candidate"
  - audit_handoff_summary.compile_support_by_ticker.<TICKER>.final_action_candidate = "REPLACE_EXISTING"
- mini_reanchor_candidate / full_reanchor_candidate 判定：
  - 若只有 distance_to_highest_live_limit_pct breach，且 abs(baseline_drift_pct) 仍在 role tolerance 內，優先使用 "mini_reanchor_candidate"。
  - 若 abs(baseline_drift_pct) 也 breach，或 live ladder 整體明顯 stale，使用 "full_reanchor_candidate"。
8B.1A) Full-Reanchor Complete Template Ladder Rebuild Rule（NEW, MUST）

- 本規則處理 existing buy open order 被判定為 full_reanchor_candidate 時，replacement submit leg 應如何重建 ladder shape。
- 若 anchor_decision_draft / anchor_decision = "full_reanchor_candidate"：
  - Strategy A 不得預設 preserve current live partial step shape。
  - Strategy A 必須優先從 Strategy Settings.buy_order_template_map 對應 role bucket 重建完整 template ladder。
  - 對 role_layer = "sector_alpha_tilt"，必須使用 buy_order_template_map.sector_alpha_tilt。
  - rebuilt replacement submit leg 必須使用完整 map bucket：
    - template_id
    - draft_packet_shape
    - ordered_step_names
    - step_offsets_vs_anchor
    - step_budget_weights 或本規則允許的 fitted step_budget_weights
    - default_plan_type
    - default_time_in_force
    - default_expiry_if_gtd
- current live order 若只剩部分 steps，例如只剩 L3 / L4，不得導致 full_reanchor_candidate 的 replacement submit leg 也只剩 L3 / L4。
- full_reanchor_candidate 的正確語意：
  - cancel leg：必須逐 step 取消 current live SSOT 中實際存在的 live steps。
  - submit leg：必須用 current_last_close 作新 anchor，重建完整 template ladder。
- 因此：
  - REPLACE_EXISTING cancel leg 可保留 current live partial shape，例如只取消 L3 / L4。
  - REPLACE_EXISTING submit leg 不得保留 partial live shape；若 template map 有 L1 / L2 / L3 / L4，submit leg 必須輸出 L1 / L2 / L3 / L4。
- full_reanchor_candidate 預設欄位收斂：
  - preserve_live_step_shape = false
  - live_step_count = null
  - live_step_count_after_submission 不得放在 top-level live_step_count；必須放在 compiled_preview_if_deterministic.live_step_count_after_submission
  - current live step count 必須只保留在 current_live_step_count / current_live_order_steps_summary / current_live_order_qtys_summary 這類 current-live SSOT 欄位中
  - ordered_step_names = Strategy Settings.buy_order_template_map.{role_bucket}.ordered_step_names
  - step_offsets_vs_anchor = Strategy Settings.buy_order_template_map.{role_bucket}.step_offsets_vs_anchor
  - anchor_baseline_last_close = current_last_close
  - anchor_price_asof = current_last_close_asof
  - draft_packet_shape = Strategy Settings.buy_order_template_map.{role_bucket}.draft_packet_shape
  - plan_type = Strategy Settings.buy_order_template_map.{role_bucket}.default_plan_type
  - time_in_force = Strategy Settings.buy_order_template_map.{role_bucket}.default_time_in_force
  - expiry_if_gtd = Strategy Settings.buy_order_template_map.{role_bucket}.default_expiry_if_gtd
- mini_reanchor_candidate 可保留 current live step shape，前提是:
  - only reachability breach, not baseline drift breach
  - current live step shape is complete enough for the intended execution role
  - compiled_notional <= proposed_budget
  - why 明確說明只是 mini reanchor, not full rebuild
- full_reanchor_candidate 只有在 Strategy Settings 明確提供：
  "allow_full_reanchor_preserve_live_partial_step_shape": true
  且 why 提供 mandate-based reason 時，才可保留 partial live step shape。
- 不合格 reason 包含但不限於：
  - "preserve live shape by default"
  - "avoid changing order count"
  - "easier to compile"
  - "current live orders only have L3/L4"
  - "no deterministic new-budget target"
  上述理由不得作為 full_reanchor 保留 partial live ladder 的充分理由。

Full-reanchor whole-share budget-fit rule（NEW, MUST）:
- Strategy A 在 full_reanchor_candidate 重建完整 template ladder 時，必須避免因單價高、整股 floor、或 partial live ladder carry-forward 而造成 material underdeployment。
- 若 current live order 是完整 template ladder 的 subset，例如 current live only has L3 / L4 while template map has L1 / L2 / L3 / L4：
  - Strategy A 應優先嘗試 deterministic fitted ladder sizing：
    (1) 對 current live 中仍存在且仍屬於 full template 的 deeper steps，保留其 current live shares 作為 target_step_share_vector 的初始值；
    (2) 對 full template 中缺失的 shallower steps，若 proposed_budget 足以容納每個 missing step 至少 1 share，則補 1 share；
    (3) 若上述 target_step_share_vector 的 compiled_notional <= proposed_budget，則可使用該 vector 作為 intended full-reanchor submit sizing；
    (4) 若仍有 residual cash 且不會超過 proposed_budget，可依 deterministic budget-fit 目標增加 shares，使 compiled_notional 最大化但不超過 proposed_budget；tie-breaker 優先選擇較接近原 template risk shape、其次才是更深 rung。
  - 例：若 current live 是 L3:2 / L4:2，完整 template 是 L1/L2/L3/L4，且 same-budget 可容納，Strategy A 可產生 L1:1 / L2:1 / L3:2 / L4:2，而不是只提交 L3:2 / L4:2。
- 若使用 target_step_share_vector，Strategy A 必須將其轉換為可由 Strategy C 現有 Budget-fit compile rule deterministic 重現的 step_budget_weights：
  - step_budget_weights 必須 sum to 1.0（允許 ±0.001）
  - 對每個 step，必須滿足：
    floor(proposed_budget × step_budget_weight_i / limit_price_i) = target_step_share_vector_i
  - 若無法找到合法 step_budget_weights 讓 Strategy C 重現 target_step_share_vector，則不得輸出該 fitted vector；必須改用 default map step_budget_weights 或標記 compile blocker。
- 若 default map step_budget_weights 會導致 material residual_cash_not_allocated，而 fitted ladder sizing 可在不超過 proposed_budget 的前提下明顯提高 compiled_open_order_notional，Strategy A 應優先使用 fitted ladder sizing。
- material residual threshold:
  - residual_cash_not_allocated >= min(lowest_full_template_limit_price, max(500.00, proposed_budget × 0.15))
- 若 full_reanchor_candidate 無法使用完整 template ladder deterministic compile：
  - 不得退回 KEEP_EXISTING
  - 不得退回 partial L3/L4-only submit leg
  - 必須在 BUY_SIDE_DELTA_TABLE.why 以 "COMPILE_BLOCKED: FULL_REANCHOR_COMPLETE_LADDER_REBUILD_FAILED:" 開頭
  - 必須在 ASSUMPTIONS_AND_DATA_GAPS 記錄：
    "FULL_REANCHOR_COMPLETE_LADDER_REBUILD_FAILED"
  - audit_handoff_summary.audit_handoff_blockers 必須加入：
    "FULL_REANCHOR_COMPLETE_LADDER_REBUILD_FAILED"
- 若 threshold breached 但 replacement 無法 deterministic compile，Strategy A 不得靜默 KEEP_EXISTING；必須：
  - 在 BUY_SIDE_DELTA_TABLE.why 以 "COMPILE_BLOCKED:" 或 "REACHABILITY_BREACH_HOLD_FOR_WEEKLY_REVIEW:" 開頭
  - 在 ASSUMPTIONS_AND_DATA_GAPS 記錄 "UPSTREAM_EXECUTION_DATA_GAP" 或 "UPSTREAM_OR_PORTFOLIO_LIVE_STATE_GAP"
  - 在 audit_handoff_summary.audit_handoff_blockers 中加入對應 blocker
  - decision_builder_ready_for_audit 依既有 blocker 規則判定
- 若 Strategy A 最終仍選擇 KEEP_EXISTING despite threshold breach，why 必須明確包含：
  - breached_metric
  - actual_value
  - role_threshold
  - why_not_same_budget_reanchor
  且 why_not_same_budget_reanchor 必須是 mandate / compile / data-gap reason；不得只是 "weekly does not force reanchor"、"avoid reducing live-state notional"、"keep existing by default"。
- distance_to_lowest_live_limit_pct 只作 evidence；除非 Strategy Settings 另有 crash-bid stale rule，不得單獨觸發 REPLACE_EXISTING / CANCEL_EXISTING。
- near_edge_monitor_band 只可產生 operator note；不得在未 threshold breach 時自行觸發 REPLACE_EXISTING。

12A) Reanchor Notional Feasibility Gate (NEW, MUST)
- 若 buy-side execution draft 同時滿足以下條件：
  - order_intent = "REPLACE_EXISTING"
  - anchor_decision 屬於 "mini_reanchor_candidate" / "full_reanchor_candidate"
  - preserve_live_step_shape = true
  - preserve_live_qty_vector 存在
  - current_last_close 與 step_offsets_vs_anchor 已可取得
- 則在輸出該 row 前，必須先做 reanchor 後預算可行性檢查。
- 重算方式：
  - 以 current_last_close 作為新 anchor
  - 依 step_offsets_vs_anchor 推回各 rung 的新 limit price
  - 再用 preserve_live_qty_vector 重算 reanchored_estimated_total_notional
- 若 reanchored_estimated_total_notional <= proposed_budget：
  - 方可保留 preserve_live_qty_vector 輸出 execution draft row
- 若 reanchored_estimated_total_notional > proposed_budget：
  - 不得直接保留 preserve_live_qty_vector 輸出
  - 若可 deterministic 產生 step_budget_weights：
      - 該 row 必須改輸出 step_budget_weights
      - preserve_live_qty_vector 不得再作為 compile payload
  - 若無法 deterministic 產生 step_budget_weights：
      - 不得輸出該 execution draft row
      - 必須在 ASSUMPTIONS_AND_DATA_GAPS 註記：
        UPSTREAM_EXECUTION_DATA_GAP: reanchor notional infeasible under preserve_live_qty_vector
- Decision Builder 不得把「保留原 qty vector」與「維持原 proposed_budget」同時視為已成立，除非上述可行性檢查已通過。
