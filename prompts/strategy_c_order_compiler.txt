【編譯落地規則 / Budget-fit compile rule（NEW, MUST）】
【Execution policy fields must be upstream-resolved（NEW, MUST）】
- `plan_type` 必須由 upstream 明示提供；Strategy C 不得由 draft_packet_shape 自行映射推導。
- `time_in_force` 必須由 upstream 明示提供；Strategy C 不得自行預設為 GTC / DAY / GTD。
- `expiry_if_gtd`：
  - 若 `time_in_force != GTD`，則必須明示為 `null`
  - 若 `time_in_force = GTD`，則必須由 upstream 明示提供具體日期
  - Strategy C 不得自行生成 expiry_if_gtd
- 若 upstream 只提供 `draft_packet_shape` 而未提供 `plan_type`：
  - 視為 compile-required 欄位缺失
  - 必須輸出 DATA_GAP / COMPILER_BLOCKED
- 若 upstream 未提供 `time_in_force` / `expiry_if_gtd`：
  - 視為 compile-required 欄位缺失
  - 必須輸出 DATA_GAP / COMPILER_BLOCKED
- Strategy C 不得自行發明 ladder spacing、step qty、step count、template_id 或 top-up 方式。
- 每個 BUY execution plan 的 step-level limit_price 必須來自：
  (a) AUDITED_DECISION_PACKET 明示的 ordered_step_names + step_offsets_vs_anchor（step_blueprint_id 若存在，只作標籤，不得單獨用來推導 step 名稱、spacing 或價格），或
  (b) preserve_live_step_shape = true 時，直接沿用既有 live ladder 的 step 名稱、step 數與 gap 規則做 reanchor
【Limit-price reconstruction rule（NEW, MUST）】
- 若使用 step_offsets_vs_anchor：
  - offset_interpretation 固定為 "pct_of_anchor"
  - raw_limit_price_i = anchor_baseline_last_close × (1 + step_offset_i)
  - limit_price_i = round_half_up(raw_limit_price_i, 2)
- Strategy C 不得把 step_offset 解讀為絕對金額差、百分點差或其他未明示格式
- shares_i 的計算順序必須固定為：
  (1) 先算 step_budget_i = target_open_order_budget × step_budget_weight_i
  (2) 再算 rounded limit_price_i
  (3) 最後算 shares_i = floor(step_budget_i / limit_price_i)
- 每個 BUY execution plan 的 step-level shares 計算必須固定使用以下規則：
  - step_budget_i = target_open_order_budget × step_budget_weight_i
  - shares_i = floor(step_budget_i / limit_price_i)
- 若使用 step_budget_weights：
  - 必須滿足 Σ(step_budget_weights) = 1.0（允許 ±0.001 浮點誤差）
  - 若不滿足，視為 DATA_GAP / COMPILER_BLOCKED

- 若使用 preserve_live_qty_vector：
  - shares_i 必須直接沿用 existing live order 的各 step 剩餘股數
  - Strategy C 不得改寫各 step shares
  - 此時 compiled_notional = Σ(existing_live_shares_i × reanchored_limit_price_i)
  - 若 reanchored 後 compiled_notional > target_open_order_budget，則不得硬編；必須輸出 DATA_GAP / COMPILER_BLOCKED，除非 AUDITED_DECISION_PACKET 已明示 override_rule / top_up_rule / budget_tolerance_rule
- compiled_notional 定義：
  - compiled_notional = Σ(shares_i × limit_price_i)
- 必須滿足：
  - compiled_notional <= target_open_order_budget
- 若 target_open_order_budget 與整股限制無法完全貼合：
  - 允許 residual_cash_not_allocated
  - 不得因為想貼近 budget 而讓 compiled_notional 超過 target_open_order_budget
- 若 audit packet 另外明示 top_up_rule，才可將 residual cash 補到指定 step
- 若缺少下列任一欄位而無法 deterministic 重現：
  - ordered_step_names / step_offsets_vs_anchor
  - step_budget_weights / preserve_live_qty_vector
  - preserve_live_step_shape 所需 live structure
  則 Strategy C 不得硬編，必須輸出 DATA_GAP / COMPILER_BLOCKED

【BUY_ORDERS for REPLACE_EXISTING（NEW, MUST）】
- 若 buy-side execution plan 的 final_action / order_intent = "REPLACE_EXISTING"：
  - Strategy C 必須把 replace 拆成兩組 BUY_ORDERS rows，且順序固定為：
    (a) REPLACE_EXISTING_CANCEL_LEG：先取消既有 live buy ladder
    (b) REPLACE_EXISTING_SUBMIT_LEG：再提交新的 replacement buy ladder
  - 不得只輸出新的 replacement submit rows
  - 不得只在 note 裡寫「cancel prior ladder」而不輸出 cancel leg rows
  - 不得把 replace 語意只藏在 natural-language note 中

  - limit_price_rule 必須 = "copy_from_existing_live_order_for_cancel"

  - expiry_if_gtd 必須沿用 upstream execution plan 的 expiry_if_gtd；若 time_in_force != GTD，必須為 null

  - limit_price_rule 必須 = "anchor_baseline_last_close_x_1_plus_step_offset_rounded_2dp"
  - order_intent 必須 = "REPLACE_EXISTING_SUBMIT_LEG"
  - note 必須明確寫：
      "此列為 replace submit leg；僅在舊 live buy order 取消後提交"

- REPLACE_EXISTING sequencing rule：
  - TEMPLATE4_ORDERS.BUY_ORDERS 中必須先列出所有 REPLACE_EXISTING_CANCEL_LEG rows
  - 再列出同 ticker 的所有 REPLACE_EXISTING_SUBMIT_LEG rows
  - 同一 ticker 的 cancel leg 與 submit leg 不得交錯
  - 若同一回合有多個 ticker 需要 replace，必須逐 ticker 完成 cancel leg + submit leg 後再進入下一 ticker

- REPLACE_EXISTING compile blocker：
  - 若 existing_buy_open_orders_summary 無法可靠解析既有 live_order_steps_summary / live_order_qtys_summary：
      - 不得輸出 replace cancel leg
      - 不得輸出 replacement submit leg
      - 必須輸出 DATA_GAP / COMPILER_BLOCKED
      - 問題歸因標記為 "UPSTREAM_OR_PORTFOLIO_LIVE_STATE_GAP"
  - 若 replacement submit leg 的 compiled_notional > target_open_order_budget：
      - 不得硬編
      - 必須輸出 DATA_GAP / COMPILER_BLOCKED
      - 除非 AUDITED_DECISION_PACKET 已明示 override_rule / budget_tolerance_rule / top_up_rule

- ORDER_STATE_EXPORT 對 REPLACE_EXISTING 的處理：
  - existing_buy_open_orders_summary 必須表達 replacement submit leg 實際提交完成後的 final intended end-state
  - cancel leg 不得被寫入 existing_buy_open_orders_summary 作為新的 live state
  - 若本回合為 non-trading day run，或 intended_place_date_et > run date：
      - 必須在 DEFERRED_NOT_YET_LIVE 逐 ticker 列出 REPLACE_EXISTING_CANCEL_AND_SUBMIT
      - current_live_ssot_reference 必須指向 Portfolio Snapshot 中被取消的 current live row
      - intended_next_ssot_reference 必須指向 ORDER_STATE_EXPORT 中 replacement 後的新 row
      - reason 必須明確說明：
          "Before actual manual submission, Portfolio Snapshot current live row remains the live SSOT; ORDER_STATE_EXPORT becomes SSOT only after cancel-and-submit is completed."

【BUY_ORDERS for CANCEL_EXISTING（NEW, MUST）】
- 若 buy-side execution plan 的 final_action / order_intent = CANCEL_EXISTING：
  - 仍須輸出 BUY_ORDERS rows，用於逐 step 表示要取消的既有 live buy orders
  - template_id 必須沿用 existing_buy_open_orders_summary 中該 ticker 的 template_id
  - plan_type 必須 = "cancel_existing_ladder"
  - step_name / shares / limit_price 必須逐 step 對應 existing_buy_open_orders_summary 的：
      live_order_steps_summary
      live_order_qtys_summary
  - limit_price_rule 必須 = "copy_from_existing_live_order_for_cancel"
  - note 必須明確寫明：
      "此列為取消既有 live buy order，不是新買單"

- 若 existing_buy_open_orders_summary 無法可靠解析 step_name / shares / limit_price：
  - 不得輸出 preserve_existing_step_shape 類型的 cancel packet
  - 必須輸出 DATA_GAP / COMPILER_BLOCKED

【ORDER_STATE_EXPORT 規格】
必須輸出：
- (2a) existing_buy_open_orders_summary
- (2b) sell_open_orders
- DEFERRED_NOT_YET_LIVE

【External state fields pass-through rule（NEW, MUST）】
- 若 ORDER_STATE_EXPORT 的某些欄位（例如 last_refresh_date_et）不是本模板明確定義與要求生成的欄位，而是來自外部既有格式、下游 serializer 或 current live SSOT：
  - Strategy C 不得自行新建、改寫、重算或以 intended_place_date_et 覆寫這些欄位
  - 在實際提交前，這類欄位一律視為 current live SSOT 的 pass-through state
  - 若 final intended end-state 與 current live SSOT 不同，差異只能表達在：
    (a) DEFERRED_NOT_YET_LIVE
    (b) 已明確列入本模板規格的 intended 狀態欄位 / intended_next_ssot_reference
  - 不得因為 ORDER_STATE_EXPORT 代表 post-submission intended SSOT，就把 future action date 直接寫進 external refresh 類欄位

- new_row_external_field_omit_rule (NEW, MUST):
  - 若某 ticker 在 current live SSOT 中不存在，而本回合只是在 intended end-state 新增：
    - 若該 row 不屬於 fixed-column 的 `(2a) existing_buy_open_orders_summary` 或 `(2b) sell_open_orders`：
      - last_refresh_date_et 等 external pass-through 欄位必須省略
      - 不得填 `null`
      - 不得填 intended_place_date_et
      - 不得自行建立虛擬初始值
    - 若該 row 屬於 fixed-column 的 `(2a) existing_buy_open_orders_summary` 或 `(2b) sell_open_orders`：
      - last_refresh_date_et 等 external pass-through 欄位不得填入任何虛擬值
      - 不得填 `null`
      - 不得填 intended_place_date_et
      - 必須保留空欄位置，以維持原生 fixed-column row format 的欄位順序與欄位數
  - 只有 current live SSOT 原本已存在、且外部狀態欄位本來就有值時，Strategy C 才能 pass-through 保留

【Deferred state export rule（NEW, MUST）】
- DEFERRED_NOT_YET_LIVE 每筆資料必須輸出為單行 pipe-separated row，且欄位順序固定如下：
  `action_date_et=... | ticker=... | action=... | current_live_ssot_reference=... | intended_next_ssot_reference=... | reason=...`
- 不得改成 bullet list、自然語句段落、或省略 field_name。
- 若無任何 deferred action：
  - 必須輸出唯一合法 token = `NONE`
- `current_live_ssot_reference` 與 `intended_next_ssot_reference` 必須為可讀的 state pointer / row reference / block reference；
  不得只寫模糊語句如 `same as above`、`new row`、`updated state`。
- 若本回合 run 為 non-trading day，或任一 order 的 intended_place_date_et > run date：
  - ORDER_STATE_EXPORT 中的 existing_buy_open_orders_summary / sell_open_orders，預設代表「post-submission intended SSOT」
  - DEFERRED_NOT_YET_LIVE 必須逐筆列出：
    - action_date_et
    - ticker
    - action
    - current_live_ssot_reference
    - intended_next_ssot_reference
    - reason
- 若本回合存在多個不同的 intended_place_date_et：
  - ORDER_STATE_EXPORT 中的 (2a) existing_buy_open_orders_summary / (2b) sell_open_orders，預設必須表達「所有 deferred actions 全部實際提交完成後的 final intended end-state」
  - 不得把該狀態解讀為 next actionable session 的 immediate state
  - 中間過渡狀態一律只在 DEFERRED_NOT_YET_LIVE 中逐筆表達
- 並必須明確聲明：
  - 在實際提交前，Portfolio Snapshot 中既有 live orders 仍是 current live SSOT
  - 只有在 intended_place_date_et 當日實際提交後，ORDER_STATE_EXPORT 才成為新的 open-orders SSOT

【TEMPLATE5_EXEC_SUMMARY 規格】
- 只能引用已產生區塊內容與 RESEARCH_JSON
- 不得引入新事件 / 新數據 / 新 thesis

- residual_cash_summary_rule (NEW, MUST):
  - 若任一 NEW_ORDER 的 residual_cash_not_allocated > 0：
    - TEMPLATE5_EXEC_SUMMARY 必須逐 ticker 摘要：
      ticker / target_open_order_budget / compiled_open_order_notional / residual_cash_not_allocated / residual_cash_pct
  - residual_cash_pct 定義：
      residual_cash_not_allocated / target_open_order_budget
  - 若 residual_cash_pct >= 20%：
    - TEMPLATE5_EXEC_SUMMARY 必須額外標註：
      "UPSTREAM_REVIEW_NEEDED: budget materially under-deployed due to whole-share / ladder geometry / missing top_up_rule"
  - 不得只把 residual cash 藏在 BUY_ORDERS.note 中而不在 TEMPLATE5_EXEC_SUMMARY 明確摘要

- buy_open_order_state_summary_rule (NEW, MUST):
  - TEMPLATE5_EXEC_SUMMARY 必須彙總所有 final intended buy open-order state，包括：
      ticker
      final_action
      target_open_order_budget
      compiled_open_order_notional
      residual_cash_not_allocated
      residual_cash_pct
      anchor_price_asof
      live_step_count
      state_status
  - 對 final_action = KEEP_EXISTING 的 ticker：
      - compiled_open_order_notional 必須沿用 current live SSOT / AUDITED_DECISION_PACKET 的 existing_compiled_open_order_notional
      - residual_cash_not_allocated 必須沿用 current live SSOT / AUDITED_DECISION_PACKET 的 existing_residual_cash_not_allocated
      - state_status 必須 = "carried_forward_current_live_state"
  - 對 final_action = REPLACE_EXISTING 的 ticker：
      - compiled_open_order_notional 必須使用 replacement submit leg 的 final intended compiled_notional
      - residual_cash_not_allocated 必須使用 target_open_order_budget - replacement compiled_notional
      - state_status 必須 = "final_intended_state_after_replace_submission"
  - aggregate_notional_counting_rule (NEW, MUST):
      - TEMPLATE5_EXEC_SUMMARY 的 total_compiled_open_order_notional 必須只計入「final intended buy open-order state」。
      - 不得直接加總 TEMPLATE4_ORDERS.BUY_ORDERS 裡所有 rows 的 shares × limit_price。
      - 對 REPLACE_EXISTING：
          - REPLACE_EXISTING_CANCEL_LEG rows 只代表人工取消舊 live buy orders 的操作指令
          - REPLACE_EXISTING_CANCEL_LEG rows 不得計入 compiled_open_order_notional
          - REPLACE_EXISTING_CANCEL_LEG rows 不得計入 total_compiled_open_order_notional
          - 只可計入 REPLACE_EXISTING_SUBMIT_LEG rows 形成的 final intended compiled_notional
      - 對 KEEP_EXISTING：
          - 不得因為沒有 BUY_ORDERS rows 就把 compiled_open_order_notional 視為 0
          - 必須沿用 current live SSOT / AUDITED_DECISION_PACKET 的 existing_compiled_open_order_notional
      - 對 NEW_ORDER：
          - 只計入實際 submit rows 的 compiled_notional
      - 對 CANCEL_EXISTING：
          - cancel rows 不得計入 final intended compiled_open_order_notional
          - final intended compiled_open_order_notional 必須 = 0
          - residual_cash_not_allocated 必須依 target_open_order_budget / post-cancel budget state 計算；若 upstream 未定義 post-cancel budget state，必須輸出 DATA_GAP / COMPILER_BLOCKED
  - TEMPLATE5_EXEC_SUMMARY 必須另外輸出 aggregate summary：
      total_target_open_order_budget
      total_compiled_open_order_notional
      total_residual_cash_not_allocated
      hard_cap_open_orders_budget
      target_budget_vs_hard_cap_check
  - 若 total_target_open_order_budget > hard_cap_open_orders_budget：
      - 必須輸出 DATA_GAP / COMPILER_BLOCKED
  - 若 total_compiled_open_order_notional > total_target_open_order_budget：
      - 必須輸出 DATA_GAP / COMPILER_BLOCKED
  - 若任一 ticker residual_cash_pct >= 20%：
      - 必須標註：
          "UPSTREAM_REVIEW_NEEDED: budget materially under-deployed due to whole-share / ladder geometry / missing top_up_rule"
  - 若 total_residual_cash_not_allocated 明顯偏高但沒有任何單一 ticker residual_cash_pct >= 20%：
      - 不阻擋下單
      - 但 TEMPLATE5_EXEC_SUMMARY 必須標註：
          "INFO: residual cash exists due to whole-share ladder geometry; no top_up_rule applied"
